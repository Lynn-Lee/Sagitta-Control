# SagittaDB Enterprise 产品使用手册

本文面向 SagittaDB Enterprise 的客户管理员、DBA、研发负责人、审批人和普通查询用户，帮助团队快速理解主要功能和使用流程。

## 1. 角色说明

常见角色：

- 平台管理员：维护系统配置、用户、角色、资源组、License 和交付验收。
- DBA：维护数据库实例、审批高风险 SQL、查看性能和诊断信息。
- 研发负责人：提交 SQL 工单、查询数据、查看审批结果。
- 审批人：按流程审核 SQL 工单、查询权限和敏感操作。
- 审计人员：查看审计日志、查询历史和导出记录。

实际菜单会受 License、角色权限和客户配置影响。

## 2. 首次登录后的配置顺序

建议按以下顺序完成初始化：

1. 打开 `商业交付` -> `License 授权`，确认试用或正式授权状态。
2. 打开 `系统管理`，配置用户、角色和用户组。
3. 打开 `资源组`，创建业务资源组并分配成员。
4. 打开 `实例管理`，接入数据库实例。
5. 打开 `审批流程`，配置 SQL 工单和查询权限审批链路。
6. 打开 `商业交付` -> `交付与支持`，生成一次验收报告。

## 3. 实例管理

`实例管理` 用于维护 MySQL、PostgreSQL、Oracle、SQL Server 等数据库实例。管理员可以：

- 新建实例连接。
- 设置实例所属资源组。
- 验证连接可用性。
- 查看库表结构。
- 管理实例启停状态和备注信息。

生产环境建议为 SagittaDB 配置只读诊断账号和受控变更账号，避免使用数据库超级管理员账号。

## 4. SQL 工单

SQL 工单用于规范数据库变更流程：

1. 研发人员选择实例和数据库。
2. 填写 SQL 内容和变更说明。
3. 系统执行语法、风险和规则检查。
4. 审批人按流程审核。
5. DBA 或自动执行策略完成上线。
6. 所有操作进入审计日志。

高风险 SQL 应先在测试环境验证，并在工单中写清回滚方案。

## 5. 在线查询

在线查询用于受控的数据查询：

- 用户只能访问被授权的实例和数据库。
- 查询结果可按权限控制导出。
- 敏感字段会按脱敏规则展示。
- 查询历史会进入审计。

建议将生产查询权限按资源组和最小必要原则授予。

## 6. 查询权限

查询权限申请用于临时或长期授权：

1. 用户提交资源组、实例、数据库和有效期。
2. 审批人按流程确认用途和范围。
3. 系统按审批结果开放访问。
4. 到期后权限自动失效或需要重新申请。

审批时应关注申请理由、访问范围和有效期。

## 7. 数据字典

数据字典用于查看库、表、字段、索引和备注信息。团队可以用它统一理解业务数据结构，减少直接登录数据库查看结构的需求。

建议管理员定期补齐关键表和字段说明，让研发、测试和数据人员能在平台内自助查询。

## 8. 数据脱敏

数据脱敏用于保护手机号、邮箱、身份证号、地址、Token 等敏感字段。管理员可以配置脱敏规则，并将规则应用到查询结果和导出流程。

建议上线前至少检查：

- 关键客户信息字段。
- 员工个人信息字段。
- 业务密钥、Token 和凭证字段。
- 审计和导出场景中的敏感数据展示。

## 9. 监控与诊断

监控与诊断页面用于查看实例状态、慢 SQL、会话、容量和采集异常。Oracle 等数据库的高级诊断能力取决于现场账号权限和数据库版本。

如果页面显示权限不足或采集失败，应先确认数据库账号是否具备对应只读视图权限。

## 10. 数据归档

数据归档用于将历史数据按策略迁移或归档。使用前请先确认：

- 归档条件准确。
- 已完成备份。
- 已在测试环境验证。
- 业务团队确认查询影响。

归档任务执行后应查看任务状态和审计记录。

## 11. 审计日志

审计日志记录用户登录、SQL 工单、在线查询、导出、授权和系统配置变更等行为。审计人员可以按用户、资源、时间和操作类型筛选。

建议定期导出并归档审计记录，满足客户内部合规要求。

## 12. 商业交付与支持

`商业交付` -> `交付与支持` 提供：

- 推广就绪度检查。
- 试用和授权状态摘要。
- 客户 ID 和部署指纹确认。
- 验收报告生成。
- 脱敏诊断包导出。
- 支持矩阵和告警事件查看。

客户正式推广前，建议先完成交付向导并生成验收报告。
