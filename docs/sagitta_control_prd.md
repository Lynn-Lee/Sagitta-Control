# Sagitta Control 矢准数据库安全管控平台产品设计文档

> 文档版本：v2.2
> 适用版本：Sagitta Control v2.2 商业部署版 + v2-lite 授权体系
> 目标读者：客户决策人、售前、产品经理、实施工程师、DBA、研发负责人、审计负责人

## 1. 产品定位

Sagitta Control 是企业级多引擎数据库安全管控平台，面向数据库变更、数据查询、权限治理、运行诊断和审计合规等场景，提供统一、安全、可追溯的管理入口。

产品核心目标是让企业把数据库访问从“分散账号、人工审批、线下执行、事后追责”升级为“统一入口、权限收敛、流程审批、异步执行、全程审计”。

### 1.1 产品价值

| 价值 | 说明 |
|---|---|
| 安全治理 | 通过角色权限、资源范围、查询授权、数据脱敏和审计日志降低越权访问风险。 |
| 效率提升 | 通过 SQL 工单、模板、AI Text2SQL、主动通知和异步执行减少人工协作成本。 |
| 多引擎统一 | 统一纳管 MySQL、PostgreSQL、Oracle、MongoDB、Redis、ClickHouse 等数据库。 |
| 运维可见 | 提供会话、SQL 洞察、慢 SQL、容量和指标采集能力，支撑故障诊断。 |
| 商业交付 | 提供可部署、可培训、可运维、可扩展的企业内部数据库管控产品。 |

### 1.2 目标用户

| 角色 | 主要诉求 | 典型功能 |
|---|---|---|
| 研发工程师 | 安全查询数据，提交 SQL 上线申请，查看工单进度。 | 在线查询、查询权限申请、SQL 工单、数据字典、模板。 |
| DBA | 审核 SQL、执行变更、管理实例、诊断数据库状态。 | 工单审批/执行、实例管理、观测诊断、归档、权限审核。 |
| 运维工程师 | 部署、升级、备份、恢复、监控平台。 | 部署运维、服务巡检、日志、监控告警、备份恢复。 |
| 安全审计员 | 追踪用户访问和数据库操作，验证合规性。 | 审计日志、查询历史、通知投递日志、权限配置检查。 |
| 系统管理员 | 管理用户、角色、资源组、审批流和系统配置。 | 用户管理、角色管理、资源组、审批流、通知、第三方登录。 |

## 2. 产品范围

### 2.1 当前正式版范围

- 用户登录、本地密码策略、第三方认证接入。
- 用户、角色、用户组、资源组、权限码管理。
- 数据库实例、数据库/Schema 注册、连接测试和启停控制。
- SQL 工单提交、审批、执行、取消、详情和审计。
- 在线查询、查询权限申请、库/表级授权、查询历史。
- 数据字典、DDL 预览、字段、约束和索引查看。
- 数据脱敏规则、查询结果脱敏。
- Dashboard 统计、监控、会话诊断、SQL 洞察、容量采集。
- 数据归档申请、审批、分批执行和日志。
- 系统配置、通知配置、审批通知、操作审计。
- Docker Compose 与 Kubernetes + Helm 部署交付。
- 全站中文界面基线，包括日期选择器、日期范围选择器、表单占位、弹窗按钮和空状态；日期控件的月份、星期、`今天`、`请选择日期`、`开始日期`、`结束日期` 不允许回退为英文默认文案。
- 商业级控制台界面基线：Dashboard 统计卡、趋势图、排行图统一使用指标卡、图表卡、范围选择器和空图提示；实例管理、SQL 工单、查询历史和审计日志等高频列表统一使用页面标题说明、筛选卡、表格卡和可区分场景的空状态，减少页面之间的视觉断层。

### 2.2 当前边界

- 企业版默认 `tenant_id=1`，保留 SaaS 多租户扩展字段，但当前不提供租户计费、自助注册和租户控制台。
- MSSQL、Oracle、Elasticsearch、OpenSearch、Doris 已有最小可用实现；其中 MSSQL、Elasticsearch、OpenSearch、Doris 已补齐 SQL/任务活动或基础观测兼容层。Elasticsearch 与 OpenSearch 使用独立引擎入口和客户端，正式接入前需要在客户真实环境完成验证。
- Cassandra/ScyllaDB 按只读/元数据边界支持，覆盖连接、Keyspace/Table/Column 元数据、表 DDL、主键/索引元数据、只读 SELECT、基础健康、peer、容量估算和 compaction 历史；DDL/DML/BATCH 工单执行按交付边界关闭，读写延迟、tombstone、SSTable、cache、thread pool 等深度指标需 JMX/sidecar。
- 售前、实施和用户手册必须保持同一引擎支持口径，不得把矩阵外能力作为标准交付承诺。
- API 文档在开发环境通过 Swagger 暴露，生产环境建议关闭或仅内网访问。

## 3. 业务流程设计

### 3.1 SQL 工单流程

```text
研发提交 SQL
  -> 系统校验用户资源范围与数据库启用状态
  -> 选择或匹配审批流
  -> 快照审批节点
  -> 审批人逐级审批
  -> 审批通过后进入待执行
  -> DBA 或具备执行权限人员触发执行
  -> Celery 异步执行
  -> 写入执行结果、审计日志和通知记录
```

关键设计：

- 工单提交时不要求研发手动选择资源组，系统按用户组与资源组关系解析实例归属。
- 审批流采用快照机制，工单创建后审批模板变更不影响在途工单。
- SQL 执行由 Celery `execute` 队列处理，避免阻塞 Web 请求。
- 执行结果、审批操作和取消操作均保留审计记录。

### 3.2 在线查询流程

```text
用户选择实例和数据库
  -> 检查数据库是否启用
  -> 检查功能权限
  -> 检查资源组实例范围
  -> 检查 QueryPrivilege 查询授权
  -> 执行查询
  -> 应用最大返回行数与脱敏规则
  -> 记录查询历史
```

在线查询执行前先进行 SQL 有效性校验，再进入权限校验：

| 阶段 | 规则 |
|---|---|
| S1 语法校验 | 使用引擎方言解析 SQL，并补充括号/引号、尾随逗号、尾随运算符、半截 DDL/DCL/控制语句等本地语法检查。 |
| S2 语义校验 | 对 AST 做基础语义校验，如 INSERT 列和值数量、CREATE TABLE 列定义、ALTER TABLE ADD COLUMN 定义等。 |
| S3 类型策略 | 语法和语义均通过后，才判断在线查询是否允许该 SQL 类型；非只读 DML/DDL/DCL/控制类语句返回“不允许执行”。 |

在线查询权限采用三层校验：

| 层级 | 规则 |
|---|---|
| L1 身份/全局权限 | 超管或具备全局查询权限的 DBA 可跳过资源范围限制。 |
| L2 资源范围 | 普通用户只能访问所在用户组关联资源组内的实例。 |
| L3 数据授权 | 用户必须具备实例级、库级或表级有效查询授权。 |

查询被拒绝时，系统应返回明确原因，帮助管理员定位是身份、资源范围还是数据授权问题。

### 3.3 查询权限申请流程

```text
用户提交查询权限申请
  -> 选择实例、数据库、表和有效期
  -> 审批人审核
  -> 通过后写入 QueryPrivilege
  -> 用户获得对应范围查询和数据字典可见权
```

权限授权支持实例、数据库、表三级粒度。有效期到期后权限自动失效，历史记录保留用于审计。

### 3.4 数据归档流程

```text
用户提交归档申请
  -> 审批人审核
  -> 审批通过后进入归档作业
  -> Celery archive 队列分批执行
  -> 支持暂停、继续、取消
  -> 查看批次日志和执行结果
```

归档作为高风险操作纳入审批流和审计体系，不依赖外部 `pt-archiver`，由平台引擎层按数据库类型适配执行。

## 4. 权限与组织模型

### 4.1 v2-lite 授权模型

```text
User
  -> Role
  -> Permission

User
  -> UserGroup
  -> ResourceGroup
  -> Instance

User
  -> QueryPrivilege
  -> Instance / Database / Table
```

权限模型拆分为三类问题：

- 用户能做什么：由角色与权限码决定。
- 用户能看到哪些实例：由用户组与资源组决定。
- 用户能查询哪些数据：由查询权限决定。

### 4.2 内置角色

| 角色 | 定位 |
|---|---|
| `superadmin` | 超级管理员，绕过所有权限检查。 |
| `dba` | 全局 DBA，具备全局查询和全局监控等运维能力。 |
| `dba_group` | 资源组 DBA，仅在所属资源组范围内进行运维。 |
| `developer` | 研发用户，默认具备 SQL 提交、查询提交和查询权限申请能力。 |

| 权限码 | 说明 |

## 5. 功能模块设计

### 5.1 Dashboard

Dashboard 面向不同角色展示权限范围内的统计信息，包括在线查询概览、SQL 工单概览、实例与库概览。统计口径按当前登录用户的权限范围裁剪。

Dashboard 视觉层级采用“范围说明 + 指标卡 + 图表卡”结构。指标卡展示图标、指标名称和数值，图表卡统一坐标轴、Tooltip、Legend、空图提示和时间范围选择器，便于售前演示和客户运维人员快速扫描。

### 5.2 实例管理

实例管理负责维护数据库连接信息、连接测试、数据库/Schema 同步、启停状态和资源组关联。实例密码和 SSH 敏感字段采用 Fernet 加密存储。

数据库注册解耦实例连接和数据库名，支持手动添加与自动同步。`is_active=False` 的数据库对普通用户不可见，管理员可见并标识为已禁用。

### 5.3 SQL 工单

SQL 工单支持提交、列表、详情、审批、执行、取消、模板复用和 AI Text2SQL。AI Text2SQL 通过系统配置接入模型服务商，除 Anthropic Claude 外，也支持 OpenAI、DeepSeek、阿里 Qwen、MiniMax、Moonshot/Kimi、智谱 GLM、小米及其他兼容 OpenAI Chat Completions 的国内主流模型网关。列表按“我的工单、审批记录、执行记录”分视角展示，减少不同角色之间的信息噪声。

SQL 工单审核默认使用基于 sqlglot 的统一规则层，覆盖多引擎公共风险规则，包括无 WHERE 的 UPDATE/DELETE、高风险 DDL、DROP/TRUNCATE、SELECT *、INSERT ... SELECT 和多语句执行顺序提示。goInception 仅作为 MySQL 专用可选扩展位，不作为 v2.0 主线能力承诺。

### 5.4 在线查询与查询历史

在线查询页面采用表浏览器、SQL 编辑器、DDL/结果区组成的工作台。系统先执行 SQL 语法和基础语义校验，通过后再应用语句类型策略、权限校验、最大行数限制、脱敏规则和查询历史记录。

查询历史用于审计“谁在何时对哪个实例执行或导出了什么 SQL、返回多少行、是否脱敏、是否失败”。

### 5.5 数据字典

数据字典展示用户有权访问的数据库对象，包括字段、约束、索引和 DDL。数据字典可见范围继承查询权限，不单独创建一套授权体系。

### 5.6 数据脱敏

脱敏规则支持内置类型和自定义正则。查询执行后按字段和规则匹配脱敏，既保证研发排查效率，也降低敏感数据泄露风险。

### 5.7 运行诊断与 SQL 洞察

运行诊断包括在线会话、历史会话、SQL 样本、SQL 指纹、实时 SQL、执行计划、容量采样和采集配置。慢 SQL 与活动 SQL 数据写入平台表，便于长期分析和趋势查看。

观测中心的实例概览展示当前运行态风险。MySQL 的慢查询卡片统计当前正在执行且超过 `long_query_time` 的会话数，锁等待卡片统计当前处于锁等待或阻塞状态的会话数，不使用 MySQL 全局累计计数作为当前风险值。性能趋势中的慢查询曲线按采集快照间的累计计数差值展示“本次采集新增慢查询次数”，避免长时间运行实例因累计值持续升高而误判。

实例诊断工作台采用通用诊断框架加引擎专属面板的组合：概览、性能、容量、会话、SQL、复制、等待事件、告警和采集诊断保持统一；Redis、ClickHouse、Oracle、TiDB 等实例按 `db_type` 追加专属页签。Redis 观测通过 `INFO all`、`CLIENT LIST` 和 `SLOWLOG` 采集内存、连接、Ops/sec、命中率、Key 淘汰、复制角色、客户端会话和慢命令，并在 Redis 专属页签展示缓存命中、内存使用率和复制摘要。ClickHouse 观测通过 `system.metrics`、`system.events`、`system.asynchronous_metrics`、`system.disks`、`system.processes` 和 `system.tables` 采集连接、当前查询、查询计数增量、失败查询、内存、磁盘、表容量和活动 SQL，并在 ClickHouse 专属页签展示磁盘、内存、写入和查询风险。TiDB 专属页签展示 Token 使用率。

SQL 洞察按引擎能力选择采集来源。MySQL 使用 `performance_schema` 慢 SQL 摘要；StarRocks、Doris、TiDB 等活动型引擎优先使用当前 SQL 活动或会话视图作为 Top SQL 来源，避免复用 MySQL 专属 `performance_schema` 查询。

### 5.8 数据归档

数据归档用于将历史数据按条件迁移或清理，支持审批、分批执行、暂停、继续、取消和批次日志。归档执行结果纳入通知和审计。

### 5.9 系统管理

系统管理包括用户、角色、用户组、资源组、审批流、系统配置、通知配置、第三方认证和操作审计。认证、通知、AI、平台名称与 Logo 等运行时配置存储在 `SystemConfig` 表中，可通过页面修改，无需重启服务。用户批量导入支持按模板中的用户组名称自动创建缺失用户组，并在导入结果中保留总数、新增、更新、失败统计和失败明细下载，同时展示本次自动创建的用户组数量。

审批类主动通知采用站内通知兜底、外部应用消息增强的双通道设计。SQL 工单、数据归档、查询权限和监控权限在提交后通知当前审批节点用户；审批流转后通知下一级审批用户；最终审批通过、驳回或取消后通知申请人。站内通知在顶部通知入口展示未读数和最近消息；飞书、钉钉和企业微信审批通知通过企业自建应用精准推送给用户资料中的飞书 Open ID、钉钉用户 ID 和企业微信 UserID，不使用群机器人 Webhook。邮件作为未配置企业应用身份或外部应用消息失败时的兜底通道。通知投递日志支持按事件、渠道、用户和状态排查，外部通知账号缺失检查用于上线前补齐审批相关人员的通知身份。

平台品牌配置包括：

- `platform_name`：平台显示名称，用于登录页、顶部导航和浏览器标题。
- `platform_logo_url`：平台 Logo 地址或图片 data URL，用于登录页、顶部导航和 favicon；未配置时使用默认 Sagitta Control Logo。
- 前端通过公开接口 `/api/v1/system/branding/` 读取品牌信息，未登录用户也可获取登录页展示所需的非敏感配置。
- 顶部导航品牌区默认只展示 Logo 图标和英文名称 `Sagitta Control`，不再显示中文副标。
- 默认登录页 Logo 下方展示中文简称 `矢准管控`，视觉文案为 `矢 准 管 控`，品牌语使用精简版 `Aim at Data, Govern with Precision`，底部版权署名为 `Lynn-Lee`，并链接到 `https://github.com/Lynn-Lee`。
- 登录页认证入口通过公开接口 `/api/v1/system/auth-methods/` 读取 LDAP、CAS、OIDC、短信验证码、钉钉、飞书和企业微信的启用状态，只暴露布尔开关，不返回密钥或服务端地址。第三方登录入口采用纯图标展示，并通过 Tooltip 提示“使用 XXX 登录”；`LDAP`、`CAS`、`OIDC` 保持大写，短信验证码、钉钉、飞书和企业微信使用中文名称。点击未启用或未配置的企业入口时，错误提示与 DataFusionX-Enterprise 对齐为各入口的具体中文提示，例如 `飞书登录未启用或 App ID 未配置。`、`CAS 登录未启用或服务器地址未配置。`、`OIDC 登录未启用或 Client ID / Issuer 未配置。`。进入 LDAP 或短信验证码登录模式后，顶部使用紧凑返回图标和统一高度的认证标题块，输入框和登录按钮字号与账号密码登录表单保持一致，保持认证方式切换区视觉一致。

## 6. 数据安全设计

| 机制 | 设计 |
|---|---|
| 密码哈希 | `SHA-256(password)` -> `base64` -> `bcrypt(rounds=12)`，规避 bcrypt 72 字节限制。 |
| 敏感字段加密 | Fernet，加密密钥由 `base64(SHA-256(SECRET_KEY))` 派生。 |
| Token 黑名单 | 用户登出后写入 Redis；请求时检查黑名单，Redis 不可用时 fail-close。 |
| 密码策略 | 强制复杂度、默认密码改密、过期改密和到期提醒。 |
| 账号安全设置 | 右上角用户菜单提供独立的个人设置和修改密码入口；个人设置负责显示名称、邮箱和 2FA 管理，修改密码弹窗仅处理当前密码更新。 |
| 弹窗关闭策略 | 系统弹窗、抽屉和确认框禁止点击外部遮罩区域关闭，需由用户明确点击取消、关闭或返回按钮退出。 |
| 操作按钮规范 | 常规 Ant Design 按钮统一 36px 高，按钮内容采用图标 + 文字；登录页第三方登录入口、返回图标、表格行内工具等紧凑控件可使用纯图标，但必须提供明确 Tooltip 和可访问标签。主操作使用品牌蓝，查看/管理/刷新使用信息蓝，编辑使用提示橙，复制/导入/导出使用工具青，取消/返回/重置/关闭使用中性灰，删除/终止/拒绝使用危险红。 |
| 页面容器规范 | 业务页面默认使用统一 PageHeader；标题下可展示一句业务说明，右侧动作在移动端自动铺满。筛选区使用 FilterCard，表格区使用 SectionCard，空状态区分无数据、筛选无结果、权限不足和未配置场景。 |
| 操作审计 | 登录、配置、工单、查询、归档和权限变更均可追踪。 |
| 数据脱敏 | 查询结果根据规则脱敏，降低敏感数据暴露面。 |
| 权限收敛 | 功能权限、资源范围、数据授权分层控制，避免单一权限过大。 |

生产环境必须保持 `SECRET_KEY` 长期稳定。修改 `SECRET_KEY` 会导致实例密码、SSH 密钥和敏感配置无法解密。

## 7. 非功能要求

| 分类 | 要求 |
|---|---|
| 可用性 | Web、Worker、Beat、Redis、PostgreSQL 均提供健康检查，生产建议使用进程重启策略。 |
| 性能 | SQL 执行、归档、通知、采集等耗时操作异步化；查询结果受最大行数控制。 |
| 可扩展性 | 引擎层通过注册表延迟加载；新增引擎时遵循统一 EngineProtocol。 |
| 可维护性 | 业务服务不自建数据库会话，统一由路由依赖或任务上下文传入。 |
| 可观测性 | 支持日志、Flower、Prometheus、Grafana 和平台内诊断视图。 |
| 合规性 | 保留审计日志、查询历史、通知投递日志和权限变更记录。 |

## 8. 部署架构

正式部署推荐两种模式：

| 模式 | 场景 |
|---|---|
| Docker Compose 生产模式 | 中小团队、单机或虚拟机部署、企业内网交付。 |
| Kubernetes + Helm | 中大型团队、多节点、高可用和标准云原生运维场景。 |

核心服务包括：

- `frontend`：Nginx 托管前端静态文件并反向代理 API。
- `backend`：FastAPI 应用。
- `celery_worker`：执行 SQL、通知、归档、采集等异步任务。
- `celery_beat`：周期性任务调度。
- `postgres`：平台元数据数据库。
- `redis`：Celery broker、Token 黑名单和临时状态。
- `flower`：Celery 任务监控。
- `prometheus` / `grafana` / `alertmanager`：可选外围监控组件。

## 9. 商业交付说明

Sagitta Control 对外投放时建议提供以下交付件：

- 根目录 README。
- 产品设计文档。
- 用户使用手册。
- 运维管理手册。
- 固定版本 Docker/Helm 客户部署包和 License 激活信息。

当前商业部署版本为 `2.2.0`。商业授权统一接入 `License-Server-Center`，客户包模板默认授权服务地址为 `https://license.loveai.asia`。Sagitta Control 使用授权项目码 `sagitta-control`，展示名称为 `Sagitta Control`。在线激活和联网刷新由后端自动提交 `project=sagitta-control` 与兼容字段 `product=sagitta-control`，客户无需在页面手工填写项目名。授权管理页支持根据客户 ID 预览正式激活部署指纹，运营侧应使用该指纹在用户授权中心生成激活码；复制指纹时兼容 HTTPS 剪贴板能力和 HTTP 试用部署降级复制。

v2.1 商业版重点补强 Oracle 可观测性：实时会话支持 RAC 实例号、OS 进程、module/action、client identifier、等待分类、阻塞实例、PGA 和 SQL child 信息；SQL 洞察新增 `oracle_sql_monitor`、`oracle_awr_sqlstat`、`oracle_cursor_cache` 来源，并按 SQL Monitor、AWR、游标缓存、当前会话顺序自动降级。Oracle 监控保持只读诊断边界，权限不足时返回 warning，不引入破坏性诊断动作。

商业版增强边界：

- 后端商业镜像通过 Nuitka 默认编译应用模块，并通过构建门禁阻止非白名单 Python 源码或字节码缓存进入镜像。
- 前端仅交付生产 build 产物，构建阶段禁止 sourcemap 和 `sourceMappingURL`，并启用生产压缩/混淆配置。
- 在线授权使用短期本地缓存，默认 7 天内必须成功回源刷新；长期离线客户使用 challenge-response 离线授权。
- 商业发布产物包含镜像 SBOM 和签名材料，支持客户侧供应链验收。
- 发布机制参考 DataFusionX：源码 `main` 提交只跑 CI 和版本记录，`release/**` 生成 RC 候选商业包，正式 `vX.Y.Z` 标签或显式手动发布才同步 `Lynn-Lee/Sagitta-Deploy` 公开交付仓库。
- 离线授权采用 challenge-response：客户生成 Challenge，运营侧按 Challenge 签发绑定部署指纹的响应文件。
- 商业镜像启动时校验 Ed25519 签名 Manifest 和关键文件摘要；发布侧需保留镜像签名、客户包签名和 sha256 记录。
- 合同、订单或授权函需明确禁止逆向、篡改、绕过授权和二次分发。

正式上线前建议完成以下验收：

- 至少接入一个生产同构测试实例。
- 完成用户、角色、用户组、资源组、审批流配置。
- 验证 SQL 工单、查询权限、在线查询、数据字典、归档、通知链路。
- 验证授权管理页展示 `授权项目：Sagitta Control（sagitta-control）`，客户 ID 可生成正式激活部署指纹，并完成在线激活、联网刷新和离线 challenge-response 导入。
- 验证 `商业交付` → `交付与支持` 页展示推广就绪度、试用/授权状态、客户 ID、正式激活部署指纹、活跃用户/实例用量、监控采集失败数和推广前待处理项；`初始化试用环境` 可幂等创建商业试用资源组、用户组、标准审批流和演示链路数据，未接入实例时不得伪造活跃实例或保存真实数据库密码；验收报告需输出 `可推广`、`需补配置` 或 `阻塞` 结论。
- 验证备份恢复和升级回滚。
- 验证审计日志、查询历史和操作追踪可用。
